=== 6. Every route+verb has at least one covering test in tests/api/ ===
$ pnpm test:api, suite tree (from 01-test-api.txt, ms timings stripped)

  harness
      - serves GET /api/health against a migrated database
  POST /api/projects
      - creates a project and answers 201 with it
      - rejects a missing name with 400 and a structured issue list
      - rejects a blank name
      - rejects malformed JSON with the transport-level message
      - rejects a non-object JSON body
      - rejects an unknown key
  GET /api/projects
      - returns a bare array containing the fixture — no envelope
  PATCH /api/projects/[projectId]
      - renames a project and returns the updated row
      - answers 404 with the action's own message for an unknown id
      - answers 400 for a malformed id segment, before any lookup
      - rejects an empty patch
      - lets the URL win over a projectId smuggled into the body
  DELETE /api/projects/[projectId]
      - answers 409 with the verbatim block message while a task remains
      - answers 404 for an unknown id
      - answers 400 for a malformed id segment
  GET /api/projects/[projectId]/statuses
      - returns the seeded defaults in order
      - returns an empty array for an unknown but well-formed project id
      - answers 400 for a malformed project segment
  POST /api/projects/[projectId]/statuses
      - appends the new status at the end of the list
      - answers 404 for an unknown project — createStatus raises it
      - rejects a missing name
  PATCH .../statuses/[statusId]
      - renames a status
      - reorders a status to a new 0-based position
      - toggles the completed flag
      - rejects an empty patch — the schema's refinement reaches the wire
      - answers 404 when the status belongs to a different project
      - answers 400 for a malformed status segment, before the scope check
  DELETE .../statuses/[statusId]
      - deletes an unused, non-last status and renumbers the survivors
      - answers 409 while a task still uses the status
      - answers 409 for the last remaining status
      - answers 404 when the status belongs to a different project
  GET /api/projects/[projectId]/priorities
      - returns the seeded defaults in order, with exactly one default
      - returns an empty array for an unknown but well-formed project id
      - answers 400 for a malformed project segment
  POST /api/projects/[projectId]/priorities
      - appends the new priority and never makes it the default
      - rejects an isDefault field on create
      - answers 404 for an unknown project
  PATCH .../priorities/[priorityId]
      - renames a priority
      - reorders a priority to a new 0-based position
      - moves the default flag so exactly one remains
      - rejects isDefault: false with a 400
      - rejects an empty patch
      - answers 404 when the priority belongs to a different project
      - answers 400 for a malformed priority segment
  DELETE .../priorities/[priorityId]
      - deletes an unused, non-last priority and renumbers the survivors
      - reassigns the default when the default itself is deleted
      - answers 409 while a task still uses the priority
      - answers 409 for the last remaining priority
      - answers 404 when the priority belongs to a different project
  POST /api/tasks
      - applies the project's first status and default priority
      - answers 409 for a status belonging to another project
      - answers 409 for a priority belonging to another project
      - answers 404 for an unknown project
      - rejects a missing title and an unknown key
  GET /api/tasks
      - filters by project
      - combines project, status, priority and q
      - searches descriptions as well as titles
      - hides completed tasks by default and reveals them on request
      - answers 400 for an uncoercible includeCompleted
      - answers 400 for a malformed filter id
      - treats empty filter values as absent
  GET /api/tasks/[taskId]
      - returns the nested project/status/priority view
      - answers 404 for an unknown id and 400 for a malformed one
  PATCH /api/tasks/[taskId]
      - edits a title and moves a status
      - clears a description with an explicit null
      - answers 400 for a projectId in the body — immutability
      - rejects an empty patch
      - answers 404 for an unknown id
  DELETE /api/tasks/[taskId]
      - returns the deleted task's id and title
      - answers 404 for an unknown id
  /api/chat-state
      - reads an empty snapshot before anything is written — never 404
      - round-trips events and session
      - overwrites the previous snapshot on a second PUT
      - rejects a non-array events field
      - rejects an unknown key
      - rejects an absent session — absent is not null

  18 route+verb suites plus the harness suite = 19 suites, 77 tests. Compare
  the suite names against section 1's verb sets: every §2.3 verb has a suite,
  and no suite exists for a verb that is not in §2.3. GET and PUT /api/chat-state
  share one suite (the first three tests cover GET+PUT round-tripping).
